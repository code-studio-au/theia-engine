# Theia Networking, Authoritative Server and Persistence

## Server languages and architecture

Rust simulation workers: authoritative ECS, movement/collision, combat, AI, navigation, group replication, Quinn networking hot path. Go: accounts, authentication, social/guild/chat infrastructure, orchestration, administration, higher-level service APIs. Avoid per-entity/per-tick Rust↔Go calls. Clear single-writer ownership per authoritative state domain (movement, inventory/economy etc.). A server GPU is optional for batched jobs only; don't introduce CPU↔GPU waits for every combat query.

## QUIC selection (LOCKED)

- Use QUIC protocol implemented by **Quinn** in Rust. Separate application replication format from transport.
- `DATAGRAM`: supersedable sequenced movement and snapshots, possibly recent-input redundancy and priority/age budgets.
- Reliable streams: gameplay requests requiring outcomes, lifecycle and state repair, inventory/transactions, chat, bounded zone state. Streams are ordered within a stream and share connection congestion capacity; do not send all combat updates on one blocking ordered stream.
- QUIC crypto remains mandatory; AES-GCM/ChaCha from audited stack, modern hardware acceleration. No custom RUDP, no plaintext gameplay workaround. Custom event-loop `quinn-proto` only after profiling demonstrates a substantial bottleneck.
- QUIC DATAGRAM application state needs own baseline ACKs/versioning; transport ACK != component applied ACK. Replay protection, idempotency, 0-RTT safety for state-changing commands, bounded queues, packet pacing/congestion awareness.

## Data-oriented replication / cohorts (AGREED)

1. Changed component stream generated by authoritative simulation; encode canonical region-relative values with stable component/version/precision identifiers, **once per reusable representation**.
2. Flat-grid spatial cohorts and semantic cohorts (party, encounter, tracked target) produce shared candidate sets; every recipient still gets authorization filters.
3. Per-client relevance, network LOD, baseline and bandwidth budget; individual packet finalization and QUIC encryption. No actual multicast over QUIC.
4. Distinguish push updates (sparse events) vs recipient-driven snapshots (dense movement). Maintain inverted indexes cell→interested cohorts and cohort→client subscriptions; avoid uncontrolled N×M work.
5. Shared delta caching only for compatible acknowledged baseline/version combinations. Bounded caches and full-state repair fallbacks.
6. Packet buffers pooled; minimize app copies and allocations; QUIC may still encrypt/copy into final transport buffers.
7. Critical events reliably transmitted or explicitly repaired; ordinary movement supersedes old queued state.

## Hierarchical NetLOD / crowd aggregates (AGREED)

Near/important: exact individual state and interactions. Mid: identities with lower update rates/precision. Far: versioned aggregate descriptors (population, distribution, appearance, flow, event-level visual metadata) that GPU reconstructs as **visual-only proxies**. Distant aggregates cannot fabricate authoritative spells/deaths or replace exact replication for relevant targets, party members, interactables, combatants. Transitions need generational versions, promotion baselines, stable seeds and masking to avoid duplication/popping. Client budget/congestion changes visual density without altering game rules.

## Server authority and movement

Non-blocking ordinary characters remove pairwise physical solver work, not combat spatial queries. Authoritative server validates movement vs static world collision, ability legality, timing, target/range, line of sight, cooldowns, health and inventory. Client GPU may predict/smooth locally but server accepts only legitimate commands. Remote snapshots interpolated; bounded extrapolation. Use separate network/simulation/screen clocks.

## Authority partitioning and live updates

Simulation owner map: partition→worker + monotonically increasing authority epoch. Content streaming cells != simulation partitions. Stable gateway retains Quinn connection while routing to new worker during upgrades. State handoff requires consistent ECS snapshot, accepted input sequence cutover, timers, relevant journal position, script/data definition versions, fencing of old writer. Hybrid spatial/encounter authority **provisional** and must be validated when severe battlefield scaling is needed. No 10k-player performance claim.

## Persistence (PROPOSED)

PostgreSQL for ACID currency, item ownership, inventory, trades, meaningful progression and account state. Strict durable commit before acknowledging valuable transfer; idempotent operations and transactional outbox. Avoid per-frame writes. Mutable persistent gameplay/world objects get ordered journals plus coherent region snapshots, with snapshot sequence and replay boundary; ephemeral positions need only checkpoint policy. Immutable environment geometry stays in content-addressed asset store. Use domain repositories and versioned schemas instead of persisting raw ECS archetype chunk bytes. Specialized distributed KV/log infrastructure only for demonstrated needs.

## Benchmark metrics

Packet-processing cycles/packet, p99 latency, useful updates/sec, recipient–entity delivery count, shared-encoding cache hit rate, baseline repair, per-client bytes/queue age, contention, server tick p99, cross-worker traffic, DB commit p99. Distinguish transport crypto cost from replication/interest cost.

## M7 actual bounded movement prototype

A separate pure Rust `theia-sim` store and headless `theia-server-lab` now
qualify server-owned fixed-tick movement. This is an early parallel M7 slice,
not a networked server or full authoritative ECS. Dense ID/position/intent/expiry/
controller columns and a logical-ID row map implement single-writer ownership.
The server supplies world IDs; the prototype has no persistence identity
registry. Connection contexts are issued per world/session and must be bound by
a future authenticated transport, never accepted as client packet credentials.

Clients supply only direction axes and monotonically increasing sequence.
Admission queues input; it does not acknowledge completed movement. Latest
accepted direction wins within a tick, and each actor moves once. Bounded
global/per-session queues reject pressure without consuming retry sequence.
Held direction expires after a server-defined tick count. Client time/destination/
speed are not authority inputs. Immutable scene/rules are server-owned.

The qualification uses integer millimetres on a Z=0 floor, static rectangles
and axis-aligned square actor footprints. Speed normalization rounds
conservatively; exact rational slab intersection prevents swept tunneling.
Ordinary actors never block each other. Whole moves into world/obstacle contact
are rejected; sliding, meshes/capsules/slopes/caves/flight and navigation remain
unimplemented. Prototype default 50 ms/3000 mm/s/250 mm half extent/three-tick
input hold are local test values, not approved engine/network policy constants.

Administrative spawn/despawn occur at tick boundaries, with logical identity
independent of dense row placement. Character respawn issues a fresh context;
stale queued commands are cancelled. Snapshots/changes are copied immutable
values, not writable authority. Combat, interactions, reliable gameplay outcomes,
Quinn, replication, persistence and worker handoff remain future gates.
